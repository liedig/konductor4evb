# Decision Log

This document tracks architectural decisions, implemented changes, and deferred technical debt for the EventBridge Nexus project. It serves as a quick reference for understanding why the system is built the way it is.

## How to Use This Document

- **Implemented Decisions**: Review these when you need context on why something was built a certain way
- **Deferred Decisions**: Check here before starting new work - these are known issues that may affect your changes
- **Adding New Entries**: When archiving an OpenSpec change, add a row to the appropriate table

## Implemented Decisions

| 2026-04-14 | domain-management-redesign | Domain Management | Single domain table, sync decide, workflow-owned events | Merged domains + registration requests into one table. Decide endpoint is synchronous (API GW → Lambda, no SQS). Approval workflow solely owns approval/rejection events and DDB status updates. All Step Functions use YAML + JSONata. SES notifications for approval requests and rejections. Update command is metadata-only (no status transitions). Status model: PENDING_APPROVAL → APPROVED → PROVISIONING → ACTIVE, with REJECTED, PROVISIONING_FAILED, INACTIVE. |
| 2026-04-14 | github-ci-templates | CI / DevEx | Gitflow branching, three-stage CI, toolchain pinning | Gitflow model with `develop` and `main` branches. CI workflow runs check → test → build sequentially (fail early on cheap checks). Rust toolchain pinned to stable via `rust-toolchain.toml`. `cargo-lambda` and `aws-sam-cli` installed via pip in CI. `Swatinem/rust-cache` for build caching. Makefile `check` target mirrors CI check job for local/CI parity. |
| 2026-04-14 | unit-test-foundation | Testing | Pure-function unit tests first, trait-based mocking deferred | Added inline `#[cfg(test)]` modules covering all pure/extractable logic: DomainStatus serde & Display, API response helpers, DynamoDB attribute helpers, domain name validation, and email body generation (approval & rejection). Trait-based AWS SDK mocking deferred to a future change — current tests cover deterministic logic without needing network calls. Email body `format!()` extracted into standalone functions to enable testing without SES. |
| 2026-04-16 | nexus-provisioning-enhancements | Cross-cutting | Rebrand to EventBridge Nexus, naming convention flip, saga rollback, account detection, RAM namespace sharing | **Rebrand**: Renamed from "EventBridge Control Plane" to "EventBridge Nexus" — reflects that it's an integration platform, not a control/data plane split. Event source prefix changed to `nexus.domain-management`, bus renamed to `nexus-bus`, trust role to `nexus-trust-role`. **Naming convention**: Flipped from `{env}-{org}-{domain}` to `{org}-{env}-{domain}` so resources group by org/domain rather than environment. Domain namespace defined as `{org}-{domain}` (environment-independent). **Saga rollback**: Provisioning workflow now implements compensating transactions — on failure, walks backwards through created resources and deletes them before marking PROVISIONING_FAILED. Best-effort cleanup with error tracking. **Account detection**: Provisioning workflow queries `by-owner` GSI to detect first-time accounts; approval notification email flags new accounts with trust-stack deployment advisory. **RAM sharing**: Domain namespaces stored as SSM Advanced Parameters at `/namespace/{domain}`, shared org-wide via AWS RAM resource share. Domain accounts can discover domains locally without cross-account IAM. |
| 2026-04-16 | provisioning-event-cleanup | Provisioning | Remove intermediate event, rename outcome events to Provisioning | Removed `DomainCreationStarted` intermediate event — no consumers, and `PROVISIONING` domain status already signals that provisioning is underway. Renamed outcome events from `DomainCreationSucceeded/Failed` to `DomainProvisioningSucceeded/Failed` — the workflow provisions infrastructure, it doesn't create the domain (that happens during registration). Aligns with existing `PROVISIONING` / `PROVISIONING_FAILED` status values. Moved `isNewAccount` flag from the removed started event to the succeeded event payload. |
| 2026-04-17 | extract-notifications-stack | Notifications | SES identities extracted into optional sibling stack, conditional core deployment | SES email identity management moved from the Nexus core stack into a standalone `notifications-stack.yaml` template. Core stack makes `ApprovalFromEmail`/`ApprovalToEmail` optional (empty-string defaults) and guards notification Lambda functions, log groups, EventBridge rules, and IAM permissions behind a `NotificationsEnabled` CloudFormation condition. When notifications are disabled, the core stack deploys without SES resources; the approval workflow still runs (task-token-based) but operators must approve via direct API call. Same-region constraint: the notifications stack must deploy in the same region as the core stack because SES identities are regional. Design intent: decouple core deployment from SES verification lifecycle, enable testing without email, and leave the door open for alternate notification transports later. |
| 2026-04-18 | installation-guide | Documentation | Single installation doc, README becomes pointer | Created `docs/installation.md` as the single runnable end-to-end installation guide covering the three-stack deploy model (notifications, core, trust), prerequisites, smoke-test walkthrough, troubleshooting, and uninstall. Replaced the README's "Getting Started" section (which had duplicated and incomplete deploy steps) with a pointer to the installation guide. Rationale: a single doc eliminates drift between README and installation instructions; an operator following one doc from start to finish is less likely to miss a step. |
| 2026-04-22 | multi-env-domain-provisioning | Provisioning | Multi-env provisioning, three-workflow split, all-or-nothing, platform-configured env list | Every approved domain is now provisioned across the full list of environments configured on the platform (e.g., `dev,staging,prod`) rather than just one. **Platform-configured**: the list comes from a new `Environments` SAM parameter (`CommaDelimitedList`, default `dev,staging,prod`) and is NOT supplied per registration — domain requesters cannot override it. The command handler stamps the current list onto the domain record at registration time so approvals run against a stable snapshot. **Three-workflow split**: the monolithic `ProvisioningWorkflow` is replaced by `provision-domain.asl.yaml` (outer coordinator), `provision-env.asl.yaml` (per-env resource creation with inner saga), and `deprovision-env.asl.yaml` (idempotent per-env teardown). The outer workflow fans out via a `Map` state with unbounded concurrency. **All-or-nothing contract**: if any env's inner execution fails, the outer workflow runs `deprovision-env` over every env that had succeeded and moves the domain to `PROVISIONING_FAILED`. `DomainProvisioningFailed` carries `failedEnvironment`, `failedStep`, `errorCode`, `errorMessage`, and aggregated `compensationErrors`. **Namespace + RAM at domain level**: the SSM parameter (`/namespace/{domain}`) and RAM share are created once above the Map and are never rolled back — they are env-independent and safe to reuse on retry. **Trust role env-independent**: the cross-account trust role is renamed from `{org}-{env}-nexus-trust-role` to `{org}-nexus-trust-role` with resource scopes broadened from `{org}-{env}-*` to `{org}-*`, so one role per domain account covers every env. **Parameter rename**: the `OrganizationArn` SAM parameter was renamed to `AwsOrganizationArn` to disambiguate the AWS Organizations service ARN from the `Organization` short identifier used in Nexus resource naming — the two had almost identical names but are unrelated concepts. `deprovision-env` is intentionally reusable as the future `DELETE /domains` primitive. |
| 2026-04-24 | nexus-platform-drop-environment | Platform | Nexus is a singleton per org — drop `Environment` from platform resources | Nexus itself does not have a `dev`/`staging`/`prod` concept — it is an integration platform deployed once per organization. The `Environment` SAM parameter on the core stack was a category error: it belongs one layer down, to the **domains Nexus provisions**. **Template rename**: `template.yaml` → `nexus-core-stack.yaml` to match the sibling-stack naming convention (`notifications-stack.yaml`, `trust-stack.yaml`) and make the file's purpose explicit. **samconfig split**: single `samconfig.toml` split into `samconfig-core.toml` and `samconfig-notifications.toml` — each stack now has an isolated deploy config invoked with `--config-file`. **Platform resource rename**: all `${Organization}-${Environment}-<thing>` resource names changed to the fixed `nexus-<thing>` pattern (nexus bus, domains table, DLQs, IAM roles, API Gateway, every Lambda + log group, state machines, EventBridge rules) — Nexus is a singleton per AWS account, so neither org nor env prefix is needed. The domain-account trust role is the one exception (`${Organization}-nexus-trust-role`, kept org-scoped so multiple orgs sharing a domain account don't collide). Domain resources (`{org}-{env}-{domain}-*`) keep env scoping because a single domain legitimately has per-env resource sets. **API stage**: `StageName` becomes static `v1` (no longer env-indexed). **`ENVIRONMENT` Lambda var removed** — grep-confirmed no Rust consumer. **Reserved name**: `nexus` is now rejected in the register-domain validation path so no domain can collide with the platform namespace. **Makefile hardening**: `AWS_REGION` defaults via `aws configure get region`; `$(error …)` guards on `APP_ACCOUNT_ID`, `OWNER_EMAIL` (smoke), and `NOTIFICATION_SENDER_EMAIL`, `PLATFORM_OPERATOR_EMAIL` (deploy-notifications). **Breaking for existing deployments** — every platform resource is renamed, so CloudFormation treats it as delete+create. Acceptable since Nexus is pre-production. |
| 2026-06-26 | add-trust-stack-deploy | Installation / DevEx | Makefile targets for trust stack deploy/teardown with auto-fetched role ARNs | Added `deploy-trust` and `teardown-trust` Makefile targets. `deploy-trust` auto-fetches `NexusFunctionRoleArn` and `ProvisioningWorkflowRoleArn` from the deployed `nexus-core` stack outputs using the platform account credentials, eliminating manual copy-paste of role ARNs. Uses `aws cloudformation deploy` (not `sam deploy`) since `trust-stack.yaml` is plain CloudFormation with no SAM transforms. Accepts `APP_PROFILE` (required, AWS CLI profile for the target domain account) and `ORGANIZATION` (optional, defaults to `acme` matching `samconfig-core.toml`). Stack named `nexus-trust` for consistency with `nexus-core`/`nexus-notifications`. `docs/trust-stack-deployment.md` updated to reference the Makefile target as the primary deployment method, retaining the manual `aws cloudformation deploy` command as an alternative for advanced use cases. |
| 2026-06-26 | domain-name-as-primary-key | Domain Management | Replace UUID domainId with domainName as DynamoDB partition key and sole domain identifier | Replaced UUID (`domainId`) with `domainName` as the DynamoDB partition key, aligning with DDD/EDA principles where the domain name IS the bounded context identifier. Global name uniqueness is an intentional governance feature forcing explicit bounded-context decisions. Removed the `by-name` GSI (redundant with partition key). Uniqueness now enforced atomically via conditional PutItem with `attribute_not_exists(domainName)`, eliminating the pre-write GSI query and its race condition. API paths changed from `/domains/{domainId}` to `/domains/{domainName}`. Event payloads dropped `domainId` from all 8 event types. Documented account-per-domain as an explicit design principle: one AWS account hosts one domain's resources, with primary/secondary owner model where secondary owners are co-managers acting as backup decision-makers. Breaking change for any event consumers keying off `domainId`. |
| 2026-07-15 | add-event-subscriptions | Event Streams | Schema-first subscriptions: latest-version pinning, resource-policy delivery, event-streams table as source of intent | **Schema-first**: consumers subscribe to a schema contract — `Subscribe(consumerDomain, producerDomain, schemaName)` — never to a bus/endpoint, and always to the **latest** version, resolved and pinned per environment at subscribe time. One representation of an event at any point in time: subscribers cannot choose historical versions; pinning makes contract transitions observable and enforceable (the version-census substrate for the future evolution thread). **Canonical envelope**: `source` = env-independent namespace identity (`{org}-{domain}`, platform-derived, never free-typed), schema name = `{source}@{detail-type}` (EventBridge discovery convention, round-trips to `aws schemas describe-schema`), numeric version at `detail.metadata.schemaVersion`; mis-stamped events fail closed (non-delivery, never misdelivery). **Delivery authorization**: replaced the specced-but-never-built per-subscription bus-to-bus IAM roles with a provision-time resource policy on the consumer's app bus (platform account may `PutEvents`) — attached in `provision-env` (`SetAppBusDeliveryPolicy` step); a backfill for pre-existing domains was built then descoped (unreleased product, no installed base; operator credentials also cannot assume the trust role, which trusts only platform service roles). Subscribe/unsubscribe never touch the consumer account. **Rule materialization**: one rule per subscription per env on the producer's platform bus, named `{consumerDomain}-{detailType}` — version-agnostic (migration is a pattern update on the same rule), per-bus name uniqueness doubles as duplicate-subscription enforcement, PutRule-as-upsert gives saga idempotency; target DLQ'd to the per-env subscription DLQ via the platform `nexus-subscription-delivery-role`. **Per-env enable/disable** maps to native rule state (subscribe with prod paused; operational kill switch); disabled ≠ removed — contract and pin retained. **`nexus-event-streams` table** (PK `producerDomain`, SK `{schemaName}#{consumerDomain}`, `by-consumer` GSI, TTL) is the source of intent; EventBridge rules are the materialization — topology and version census answered without enumerating AWS resources; REMOVED records retained 90 days. **All-or-nothing activation** across envs with compensation (`activate-subscription.asl.yaml`); idempotent removal (`remove-subscription.asl.yaml`). **Zero-events alarm per subscription** (24h, missing data = breaching) — a version-pinned rule that stops matching goes silent, not to a DLQ. **Read-only schema discovery** (`GET /schemas`) merges per-env registries reporting latest version per env, making skew visible before subscribing; schema registration/evolution/RBAC explicitly deferred. Subscription id = `{consumer}.{producer}.{detailType}` (domain names cannot contain dots, so parsing is unambiguous). |
| 2026-07-16 | harden-workflow-failure-paths | Domain Management | Fixed JSONata crashes in workflow failure paths; added APPROVAL_NOTIFICATION_FAILED status; added Retry policies to all SDK task states | **Root cause**: the failure paths of `approval.asl.yaml` and `provision-domain.asl.yaml` were never exercised until real failures (SES unverified, schema-registry quota exhaustion) hit them live on 2026-07-15, revealing that the error-handling itself crashed with `States.QueryEvaluationError` — silently leaving domains stuck in `PROVISIONING`/`PENDING_APPROVAL` with no notification and no terminal event. **`provision-domain` fix**: replaced a `$exists`-guarded `$reduce` over rollback compensation errors (which returns undefined — and crashes the state — for the two most common shapes: zero envs succeeded, or rollback completed cleanly) with a JSONata array constructor (`[$rollbackResults.compensationErrors]`) that coerces undefined to `[]` and flattens for every shape. **`approval` rewrite**: registration context is now captured in a Pass state (`CaptureRegistration`) *before* the task-token wait, since `Assign` on a Task only applies on success and was leaving `$registration` unassigned on every failure path. The single `States.TaskFailed` catch is split into three routes: the `RegistrationRejected` custom error (human rejection, with `decidedBy`/`justification` parsed from the decide Lambda's JSON cause, falling back to `unknown` on a malformed cause), `States.Timeout` (7-day silence, `decidedBy: system:timeout`), and a residual `States.ALL` route for notification-infrastructure failure — previously indistinguishable from a human rejection. **New terminal status**: `APPROVAL_NOTIFICATION_FAILED` — a notification-delivery failure means nobody decided anything, so it is neither `REJECTED` (dishonest) nor `PENDING_APPROVAL` (no request is actually pending); emits a new operator-facing `DomainApprovalNotificationFailed` event with no owner-facing email (email delivery is the failed dependency). **Retry posture**: added `Retry` blocks (throttle-prone profile: 2s/5 attempts for CloudWatch/Schemas; standard profile: 1s/3 attempts for EventBridge/SQS/SSM/RAM/DynamoDB/putEvents/startExecution) to every SDK task state across all four domain-management state machines, forward and compensation paths alike, excluding deterministic business errors so they still fail fast into saga rollback. **Live-verified, not just unit-tested**: deployed to the platform account and confirmed against real executions — a registration coincidentally hit the platform's actual schema-registry quota mid-verification, reproducing the exact historical partial-failure crash shape; the outer workflow that previously died with `QueryEvaluationError` instead completed with `ExecutionSucceeded`, correctly rolled back the succeeded environments, and left the domain in `PROVISIONING_FAILED` with an accurate `compensationErrors: []`. The rejection, notification-failure, and happy-path-forward scenarios were each verified the same way via direct Step Functions executions and decide-API calls against the live stack. |
