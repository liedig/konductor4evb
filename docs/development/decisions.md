# Decision Log

This document tracks architectural decisions, implemented changes, and deferred technical debt for the Konductor for Amazon EventBridge project. It serves as a quick reference for understanding why the system is built the way it is.

## How to Use This Document

- **Implemented Decisions**: Review these when you need context on why something was built a certain way
- **Deferred Decisions**: Check here before starting new work - these are known issues that may affect your changes
- **Adding New Entries**: When archiving an OpenSpec change, add a row to the appropriate table

| 2026-04-22 | multi-env-domain-provisioning | Provisioning | Multi-env provisioning, three-workflow split, all-or-nothing, platform-configured env list | Every approved domain is now provisioned across the full list of environments configured on the platform (e.g., `dev,staging,prod`) rather than just one. **Platform-configured**: the list comes from a new `Environments` SAM parameter (`CommaDelimitedList`, default `dev,staging,prod`) and is NOT supplied per registration — domain requesters cannot override it. The outer workflow fans out via a `Map` state with unbounded concurrency. **All-or-nothing contract**: if any env's inner execution fails, the outer workflow runs `deprovision-env` over every env that had succeeded and moves the domain to `PROVISIONING_FAILED`. `DomainProvisioningFailed` carries `failedEnvironment`, `failedStep`, `errorCode`, `errorMessage`, and aggregated `compensationErrors`. **Namespace + RAM at domain level**: the SSM parameter (`/namespace/{domain}`) and RAM share are created once above the Map and are never rolled back — they are env-independent and safe to reuse on retry. **Trust role env-independent**: the cross-account trust role is renamed from `{org}-{env}-konductor-trust-role` to `{org}-konductor-trust-role` with resource scopes broadened from `{org}-{env}-*` to `{org}-*`, so one role per domain account covers every env. **Parameter rename**: the `OrganizationArn` SAM parameter was renamed to `AwsOrganizationArn` to disambiguate the AWS Organizations service ARN from the `Organization` short identifier used in Konductor resource naming — the two had almost identical names but are unrelated concepts. `deprovision-env` is intentionally reusable as the future `DELETE /domains` primitive. |

| 2026-07-15 | add-event-subscriptions | Event Streams | Schema-first subscriptions: latest-version pinning, resource-policy delivery, event-streams table as source of intent | **Schema-first**: consumers subscribe to a schema contract — `Subscribe(consumerDomain, producerDomain, schemaName)` — never to a bus/endpoint, and always to the **latest** version, resolved and pinned per environment at subscribe time. One representation of an event at any point in time: subscribers cannot choose historical versions; pinning makes contract transitions observable and enforceable (the version-census substrate for the future evolution thread). **Canonical envelope**: `source` = env-independent namespace identity (`{org}-{domain}`, platform-derived, never free-typed), schema name = `{source}@{detail-type}` (EventBridge discovery convention, round-trips to `aws schemas describe-schema`), numeric version at `detail.metadata.schemaVersion`; mis-stamped events fail closed (non-delivery, never misdelivery). **Delivery authorization**: replaced the specced-but-never-built per-subscription bus-to-bus IAM roles with a provision-time resource policy on the consumer's app bus (platform account may `PutEvents`) — attached in `provision-env` (`SetAppBusDeliveryPolicy` step); a backfill for pre-existing domains was built then descoped (unreleased product, no installed base; operator credentials also cannot assume the trust role, which trusts only platform service roles). Subscribe/unsubscribe never touch the consumer account. **Rule materialization**: one rule per subscription per env on the producer's platform bus, named `{consumerDomain}-{detailType}` — version-agnostic (migration is a pattern update on the same rule), per-bus name uniqueness doubles as duplicate-subscription enforcement, PutRule-as-upsert gives saga idempotency; target DLQ'd to the per-env subscription DLQ via the platform `konductor-subscription-delivery-role`. **Per-env enable/disable** maps to native rule state (subscribe with prod paused; operational kill switch); disabled ≠ removed — contract and pin retained. **`konductor-event-streams` table** (PK `producerDomain`, SK `{schemaName}#{consumerDomain}`, `by-consumer` GSI, TTL) is the source of intent; EventBridge rules are the materialization — topology and version census answered without enumerating AWS resources; REMOVED records retained 90 days. **All-or-nothing activation** across envs with compensation (`activate-subscription.asl.yaml`); idempotent removal (`remove-subscription.asl.yaml`). **Zero-events alarm per subscription** (24h, missing data = breaching) — a version-pinned rule that stops matching goes silent, not to a DLQ. **Read-only schema discovery** (`GET /schemas`) merges per-env registries reporting latest version per env, making skew visible before subscribing; schema registration/evolution/RBAC explicitly deferred. Subscription id = `{consumer}.{producer}.{detailType}` (domain names cannot contain dots, so parsing is unambiguous). |
| 2026-07-16 | harden-workflow-failure-paths | Domain Management | Fixed JSONata crashes in workflow failure paths; added APPROVAL_NOTIFICATION_FAILED status; added Retry policies to all SDK task states | **Root cause**: the failure paths of `approval.asl.yaml` and `provision-domain.asl.yaml` were never exercised until real failures (SES unverified, schema-registry quota exhaustion) hit them live on 2026-07-15, revealing that the error-handling itself crashed with `States.QueryEvaluationError` — silently leaving domains stuck in `PROVISIONING`/`PENDING_APPROVAL` with no notification and no terminal event. **`provision-domain` fix**: replaced a `$exists`-guarded `$reduce` over rollback compensation errors (which returns undefined — and crashes the state — for the two most common shapes: zero envs succeeded, or rollback completed cleanly) with a JSONata array constructor (`[$rollbackResults.compensationErrors]`) that coerces undefined to `[]` and flattens for every shape. **`approval` rewrite**: registration context is now captured in a Pass state (`CaptureRegistration`) *before* the task-token wait, since `Assign` on a Task only applies on success and was leaving `$registration` unassigned on every failure path. The single `States.TaskFailed` catch is split into three routes: the `RegistrationRejected` custom error (human rejection, with `decidedBy`/`justification` parsed from the decide Lambda's JSON cause, falling back to `unknown` on a malformed cause), `States.Timeout` (7-day silence, `decidedBy: system:timeout`), and a residual `States.ALL` route for notification-infrastructure failure — previously indistinguishable from a human rejection. **New terminal status**: `APPROVAL_NOTIFICATION_FAILED` — a notification-delivery failure means nobody decided anything, so it is neither `REJECTED` (dishonest) nor `PENDING_APPROVAL` (no request is actually pending); emits a new operator-facing `DomainApprovalNotificationFailed` event with no owner-facing email (email delivery is the failed dependency). **Retry posture**: added `Retry` blocks (throttle-prone profile: 2s/5 attempts for CloudWatch/Schemas; standard profile: 1s/3 attempts for EventBridge/SQS/SSM/RAM/DynamoDB/putEvents/startExecution) to every SDK task state across all four domain-management state machines, forward and compensation paths alike, excluding deterministic business errors so they still fail fast into saga rollback. **Live-verified, not just unit-tested**: deployed to the platform account and confirmed against real executions — a registration coincidentally hit the platform's actual schema-registry quota mid-verification, reproducing the exact historical partial-failure crash shape; the outer workflow that previously died with `QueryEvaluationError` instead completed with `ExecutionSucceeded`, correctly rolled back the succeeded environments, and left the domain in `PROVISIONING_FAILED` with an accurate `compensationErrors: []`. The rejection, notification-failure, and happy-path-forward scenarios were each verified the same way via direct Step Functions executions and decide-API calls against the live stack. |

| 2026-07-29 | add-cognito-access-foundation | Authorization | Cognito/OAuth interactive identity, dual API surfaces, trusted-principal propagation, OAuth-only approval — without the DynamoDB grant engine | **Dual API surfaces**: split the single IAM-auth REST API into a separate OAuth surface (`openapi-oauth.yaml`, Cognito + REQUEST authorizer) and an IAM surface (`openapi-iam.yaml`, SigV4), each at the static `v1` stage. No mixed-auth method; approval is OAuth-only. **Cognito identity**: dedicated user pool with configurable access-token lifetime, OAuth app client (no browser client secret exposed), controlled groups `platform-admin` and `platform-auditor`. **REQUEST authorizer**: Lambda authorizer validates Cognito access tokens (signature via JWKS, issuer, expiration, `token_use=access`, client/audience), maps `cognito:groups` to `GlobalRole` enum values, preserves other groups as opaque team-group identifiers, and emits route-scoped allow/deny policies (`platform-admin` = any method, `platform-auditor` = GET only). JWKS caching with refresh on unknown `kid`; authorizer-result caching disabled by default. No token material in logs or authorizer context. **TrustedPrincipal contract**: versioned, tag-based enum — OAuth variant carries subject, issuer, client ID, global roles, team groups; IAM variant carries AWS account ID as `principalId` with optional principal ARN audit provenance. Fail-closed deserialization: missing discriminator, unknown mechanism, or mixed fields is an error, never a silently reinterpreted identity. **Trusted context propagation**: VTL mapping templates inject a versioned envelope into SQS message attributes (sourced from `$context.authorizer.*` / `$context.identity.*`, never the request body); consumer handlers reconstruct `TrustedPrincipal` from the envelope and invoke `ResourceAuthorizer` before state changes; proxy read handlers parse the principal from `requestContext` for audit logging. **FoundationAuthorizer** (since renamed `IamOnlyAuthorizer`): interim `ResourceAuthorizer` implementation — allows IAM mutations, denies OAuth mutations (fail-closed) — until the DynamoDB grant engine lands. Denied commands emit the established deterministic failure outcome (EventBridge `*Failed` + SQS ack, no retry). **OAuth-only approval**: `decidedBy` is derived from the trusted OAuth principal's `principalId`, not from caller-supplied input; the `decidedBy` field is removed from `DecideRequest` and rejected by `deny_unknown_fields`. The email-link bearer GET approval path is removed; approval emails direct operators to sign in. Task tokens remain the Step Functions callback mechanism, supplied in the authenticated POST body. The decide handler verifies OAuth mechanism and `platform-admin` role (defense-in-depth) before any Step Functions callback. **Dependency**: this change establishes the identity and propagation substrate for the production authorization engine (spiked in `evaluate-authorization-engine`); enterprise federation and group-customization guidance are deferred to that change. |

| 2026-08-03 | add-grant-engine | Authorization | Production grant engine: bindings table, dual engines behind `ResourceAuthorizer`, OAuth-only binding administration — shipped dark | **Two-store split**: publisher/subscriber role bindings live in `konductor-authorization-bindings` now; subscriber entitlements get their own table in `add-subscriber-entitlements`. Different revocation semantics (bindings gate nothing materialized; entitlements gate subscriptions needing reconciliation) and different shipping schedules; DynamoDB transactions span tables, so a future cross-store mutation can still be atomic. **Stringly-typed trait retained**: the existing `ResourceAuthorizer` seam (`authorize(&TrustedPrincipal, action, resource) -> Allow|Deny`) stays — typed actions/resources would churn every consumer for no decision-quality gain; action strings are centralized constants in `konductor-common` so typos surface in tests. **Deny-as-unknown dropped**: the engine returns `Deny`; 404-vs-403 response shaping is an API-layer concern, and the spike's deny-as-unknown polish added ambiguity without security value. **No revocation worker**: publisher bindings have no materialized downstream state, so revoke is a durable conditional delete effective on the next decision — no reconciliation machinery (that arrives with entitlements). **Conditional writes + atomic audit**: creates use `attribute_not_exists` puts (idempotent re-create answers the stored binding; concurrent-revoke races map to 409), revokes use existence/state-conditioned deletes, and every mutation commits with its token-free `AuditRecord` in one `TransactWriteItems` so the audit trail cannot diverge from grant state. **Decisions are strongly consistent point reads**; the admin GSIs (`by-domain`, `by-binding-id`) are sparse, eventually consistent, and never feed an allow decision. **Binding administration is flat-verb, OAuth-only, platform-admin-only** (`POST/GET/DELETE /bindings`): the platform-admin role resolves from the controlled Cognito group, never the grant table, so administration cannot deadlock against an empty table; the IAM surface has no binding routes. **Engines ship as a pair**: `DynamoGrantEngine` (cloud) and `InMemoryGrantEngine` (fixtures) behind the same trait, with a manifest-seeded parity suite proving identical decisions; no existing consumer is rewired (dark ship) — `IamOnlyAuthorizer` (renamed from `FoundationAuthorizer`, with `FailClosedAuthorizer` → `DenyAllAuthorizer`) keeps guarding current paths until `add-publisher-apis` and `add-subscriber-entitlements` migrate them. **Model hardening**: `BindingPrincipal` deserialization runs the validating constructors, so malformed principals are unrepresentable via API bodies as well as code; global (domain-less) bindings are rejected at the model level. |
| 2026-08-05 | add-publisher-apis | Event Streams | Publisher APIs: environment-named stages, store-and-forward publish, append-only schema management — first grant-engine consumers | **Environment-named stages**: both API surfaces replaced the static `v1` stage with `dev`/`staging`/`prod` stages sharing one deployment; the stage is the environment selector, so publishers never name an environment, registry, or bus. **Flat verb endpoints**: `POST /publish`, `POST /schemas`, `POST /schemas/versions` take the domain in the body — no nested resource paths, matching the binding-admin precedent. **Store-and-forward publish**: API Gateway validates the flat `{domain, eventName, data, idempotencyKey?}` body and queues it with the trusted-principal envelope, `Environment` (from `$context.stage`), and `IdempotencyKey` (caller key or `$context.requestId`) as message attributes; the `publish-events` consumer authorizes `schema:publish` via `DynamoGrantEngine` before any resource access, requires an ACTIVE domain, resolves the latest schema version in the stage-selected registry, builds the canonical envelope, and calls `PutEvents` on the domain bus. Deterministic denials are acknowledged; everything else retries via partial batch responses (batch 10) with immutable attributes. **Envelope metadata immutability**: `publishedAt` derives from the SQS `SentTimestamp` (retries keep the original publish time) and `idempotencyKey` from the message attribute; the consumer validates the generated envelope (positive version, non-empty identity, serializable, ≤256KB) before delivery — invalid generated envelopes are processing failures, never partial deliveries. **Schema management mimics the EventBridge Schemas API**: synchronous proxy endpoints (the created version must return to the caller) mapping `CreateSchema` → 201 version 1 / 409 duplicate and `UpdateSchema` → 201 next version / 404 missing; append-only — no delete, retire, replace, or version deletion, and no registry administration permissions. **Auth engine separation**: this change consumes the `ResourceAuthorizer` decision interface only; binding persistence and administration stay with `add-grant-engine`, and both publisher functions read bindings through the reserved `konductor-bindings-table-read` managed policy. **Event-name feasibility**: schema writes validate the event name against EventBridge rule-name constraints (`rule_name`) before any service call. **Duplicate-create mapping**: the Schemas service model has no `ConflictException` for `CreateSchema`, so a duplicate's `BadRequestException` ("already exists") maps to 409 with a `code()` fallback for a future conflict code. |

| 2026-08-11 | add-subscriber-entitlements | Authorization / Event Streams | Subscriber entitlement store, coverage-gated subscriptions, revocation pipeline, entitlement-expanded catalog | **Entitlements complete the two-store model**: `konductor-authorization-entitlements` (PK consumer domain, SK `producerDomain#scopePattern`, `by-producer` GSI, by-entitlement GSI, TTL) is the subscriber half of the `add-grant-engine` split. Entitlements are environment-agnostic durable intent; `ExpiresAt` drives TTL removal at most ~4 days after expiry (DynamoDB deletes in its own window) and expiry is also evaluated logically at read time. **Scope-pattern grammar**: one additive grammar serves coverage, subscription authorization, and catalog expansion — `*` covers a whole producer domain including future schemas, an exact detail type covers all versions of one schema including future versions, and a `*` suffix covers a prefix family including future members. Patterns deliberately share by naming convention: prefixes like `Order`/`OrderItem` overlap, so name producer schemas with hygiene and treat an unintended match as one entitlement delete away — no separate catalog-language. **Entitlements are control-plane intent; EventBridge rules are compiled enforcement**: administration only writes table rows; the activation workflow compiles intent into a rule per environment, so intent travel is never blocked by enforcement failure and enforcement carries no per-subscription authorization state. **Composite resource grammar**: `subscription:environment:{id}:{env}` resources make the engine evaluate create/enable under binding *and* coverage but disable/delete under binding alone — a lapsed entitlement can never wedge an existing subscription in an unmanageable state. **OAuth-only administration with producer self-service**: create and revoke are authorized by the `platform-admin` global role *or* a `publisher` binding on the entitlement's producer domain (so producer teams share their own schemas without platform involvement); consumer-scoped lists additionally admit a `subscriber` binding. The IAM surface exposes no entitlement routes in this capability version — administration that changes other domains' access is an interactive, auditable act. **Stream-driven side-effect transport**: the entitlements DynamoDB stream carries change records — small self-describing control messages routed by record type (audit events to `konductor-bus`, revocation messages to SQS) — never business events; the two planes never mix, so control throughput, ordering, and retention tune independently of event traffic. **Revocation is reconciliation-bounded**: revoke is durable at the transaction commit and effective at the next decision immediately; the worker pipeline (stream → queue → disablement) converges existing subscriptions with idempotent writes, marker-claimed stream records (replay = no-op), and per-record partial batch failure; the hourly sweep scans every stream, re-evaluates coverage fail-closed, and disables uncovered ACTIVE subscriptions — drift windows are observable via alarms, never silent. **403-over-404**: uncovered schema targets and unauthorized subscription commands answer `403 Forbidden` with a generic body — the denial is deterministic and never oracles the existence of producer schemas or other callers' subscriptions. **`IamOnlyAuthorizer` retention**: platform-operated paths that never represent a domain owner keep the IAM guard rather than being force-migrated onto bindings they would tautologically satisfy. |
